Here's a guide to building a completely free YouTube-to-Transcript tool using GitHub Actions and Whisper.

Right now, a major obstacle is that GitHub's free runners have very limited storage (only 14GB) and no persistent GPU acceleration, so they can't process large models like Whisper in real time. To work completely within GitHub's free tier, we need a clever, hybrid approach that uses **two separate API calls**: one for YouTube's official transcripts (if available), and another for a free, server‑side Whisper endpoint.

### 🧩 A Hybrid, Completely Free Architecture

This design keeps all your code and workflow in your GitHub repository, with all heavy processing handled by free, external services.

*   **Workflow Runner**: A GitHub Actions workflow (on `ubuntu-latest`) that orchestrates the entire process. It downloads the audio/video and calls the two free transcription services.
*   **Download & Extract**: Your Python script will run inside the GitHub Actions environment and use `yt-dlp` to fetch the video's audio stream. `yt-dlp` is a powerful, actively maintained tool for downloading from YouTube.
*   **Transcription (Two Routes)**:
    1.  **YouTube Transcript API (`youtube-transcript-api`)**: First, the script will call this Python library to check if the video already has subtitles. This method is **instant and completely free**, as it doesn't require any API keys or external services.
    2.  **AI Transcription (Free-tier API)**: If no official transcript exists, it will send the downloaded audio to a free, server-side Whisper API. A reliable option is **Supadata's Free Tier**, which offers 50 free transcriptions per day and 5 requests per 10 seconds. You will need to sign up for an API key, but the tier is free.
*   **Output**: The combined transcript is saved as a text file and can be committed back to your repository or made available as a downloadable artifact.

### 📝 Detailed, Step-by-Step Implementation

Here's how to put it all together.

#### **1. Set Up Your Repository and API Key**
*   Create a new public or private GitHub repository.
*   Sign up for a free API key at [Supadata.ai](https://supadata.ai).
*   In your GitHub repository, go to **Settings > Secrets and variables > Actions** and add a new secret named `SUPADATA_API_KEY`, pasting in your key. GitHub's secrets are encrypted and are the safest way to handle credentials in your workflows.

#### **3. Create the GitHub Actions Workflow**
Create the file `.github/workflows/transcribe.yml` in your repository:

```yaml
name: YouTube to Transcript

on:
  workflow_dispatch:
    inputs:
      youtube_url:
        description: 'YouTube Video URL'
        required: true
        type: string

jobs:
  transcribe:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4
      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: '3.10'
      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install yt-dlp youtube-transcript-api requests
          sudo apt-get update
          sudo apt-get install -y ffmpeg
      - name: Run transcription
        env:
          SUPADATA_API_KEY: ${{ secrets.SUPADATA_API_KEY }}
        run: |
          python transcribe_youtube.py "${{ github.event.inputs.youtube_url }}"
      - name: Upload transcript
        uses: actions/upload-artifact@v4
        with:
          name: transcript
          path: transcript.txt
```
*This workflow is triggered manually (`workflow_dispatch`) and runs the Python script. It installs all necessary dependencies, including `ffmpeg` which `yt-dlp` needs to process audio.*

### 🔐 A Balanced Look at Privacy & Safety

*   **Where does processing happen?** The transcription using the free API (**Supadata**) happens on their servers. Your audio file is uploaded to their service for processing. This is a trade-off for using a free, serverless model.
*   **API keys are safe.** By storing your `SUPADATA_API_KEY` as a GitHub secret, it is encrypted and never exposed in your code or workflow logs.
*   **Your GitHub data.** Be aware that GitHub's default settings may use data from **public repositories** to train its AI models. You can opt out of this in your GitHub settings under "Copilot" features.
